Goal
--------------------------------------------------------------------------------
Build an internal business tool for managing client leads, project inquiries,
proposal generation, and sales workflow management.

The application should demonstrate:
- Clean architecture
- Production-ready patterns
- RBAC authorization
- AI integration
- Database design
- TypeScript quality
- Scalability considerations
- DevOps awareness

================================================================================

Frontend
--------------------------------------------------------------------------------

- TypeScript
- Tailwind CSS
- Shadcn UI
- TanStack Query
- React Hook Form

Why
--------------------------------------------------------------------------------
- Modern production-grade stack
- Excellent DX and TypeScript support
- Server Components where possible
- Client Components only when required
- Optimized data fetching and caching
- Clean and professional UI

Backend
--------------------------------------------------------------------------------
- NestJS
- TypeScript
- Prisma ORM
- PostgreSQL
- JWT Authentication
- Swagger/OpenAPI
- Multer (file uploads)

Why Prisma instead of TypeORM
--------------------------------------------------------------------------------
- Better TypeScript support
- Safer schema migrations
- Easier filtering/pagination
- Cleaner developer experience

Infrastructure
--------------------------------------------------------------------------------
- Docker
- Docker Compose

Optional DevOps

Observability
--------------------------------------------------------------------------------

- Request ID Logging

AI
--------------------------------------------------------------------------------
Primary:
- OpenAI API (optional)

Fallback:
- Local Mock Proposal Generator

Switch controlled through environment variable.

Audit Trail Metadata
--------------------------------------------------------------------------------
Purpose:
- Track before/after changes

Example:
Status changed from:
QUALIFIED
to
PROPOSAL_SENT

Stored inside Activity Logs metadata.

Soft Delete
--------------------------------------------------------------------------------
Purpose:
- Prevent accidental data loss

Implementation:
deletedAt field

Records remain recoverable.

Request ID Logging
--------------------------------------------------------------------------------
Purpose:
- Trace requests through the system

Each request receives:
X-Request-ID

Useful for:
- Debugging
- Log correlation

Refresh Tokens
--------------------------------------------------------------------------------
Purpose:
- Persistent login experience

Benefits:
- More secure than long-lived access tokens
- Better user experience

Swagger Documentation
--------------------------------------------------------------------------------
Purpose:
- Auto-generated API docs

Endpoint:
/api/docs

Benefits:
- Easy reviewer testing
- Professional API documentation

OpenTelemetry
--------------------------------------------------------------------------------
Purpose:
- Distributed tracing
- Performance monitoring

Tracks:
- Request lifecycle
- Database calls
- AI API calls

Can identify:
- Slow endpoints
- Bottlenecks
- Failure points
